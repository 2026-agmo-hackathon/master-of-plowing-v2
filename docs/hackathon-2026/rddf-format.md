# RDDF 주행 경로 파일 포맷

2026 Agritechnica 해커톤 참가자용 명세. RDDF 는 자율주행 트랙터가 따라갈
**주행 경로(웨이포인트 목록)** 를 담는 탭 구분 텍스트 파일이다. 이 문서만으로
직접 경로 파일을 만들 수 있도록, 시뮬레이터·API 서버 파서의 실제 동작 기준으로
정리했다.

파서 구현: `simulator/src/simulation/RddfParser.ts`,
`api-server/api/app.py` 의 `parse_rddf` — 두 곳은 같은 규칙을 쓴다.

---

## 1. 두 가지 형식

탭 구분 텍스트인데 열 수가 다른 **두 형태**가 돌아다니고, 파서는 둘 다 받는다.

### 8열 형식 — 좌표가 DDMMSS.ssss

`rddf.h` 의 `struct RDDF` 순서. 실디바이스 앱 리소스(`*.rddf`)가 이 형식이다.

| # | 열 | 의미 |
|---|---|---|
| 1 | `index` | 점 번호 |
| 2 | `lat` | 위도, **DDMMSS.ssss** 표기 |
| 3 | `lon` | 경도, **DDMMSS.ssss** 표기 |
| 4 | `lbo` | (예약) 파서는 읽지 않음 |
| 5 | `reserved0` | (예약) 파서는 읽지 않음 |
| 6 | `reserved1` | (예약) 파서는 읽지 않음 |
| 7 | `velocity` | 목표 속도. **부호가 주행 방향** (전진 +, 후진 −) |
| 8 | `implement` | 작업기 플래그. `1` = 내림(작업 중), `0` = 올림 |

실제 예시 (`references/agmo-app/app/res/3435256455453.rddf`):

```
0	370913.5566	193134.2696	0.100000	0.000000	0.000000	4.000000	1
1	370856.0894	193129.031	0.100000	0.000000	0.000000	4.000000	1
2	370855.9345	193128.8646	0.100000	0.000000	0.000000	4.000000	1
```

### 9열 형식 — 좌표가 십진도

해커톤 원본 코스(`3.rddf`)와 이 레포의 샘플·생성기가 쓰는 형식.

| # | 열 | 의미 |
|---|---|---|
| 1 | `index` | 점 번호 |
| 2 | `index2` | 점 번호(중복) |
| 3 | `lat` | 위도, **십진도(decimal degrees)** |
| 4 | `lon` | 경도, **십진도** |
| 5 | — | 항상 `0.0` |
| 6 | `reserved0` | (예약) 파서는 읽지 않음 |
| 7 | `reserved1` | (예약) 파서는 읽지 않음 |
| 8 | `velocity` | 목표 속도. **부호가 주행 방향** (전진 +, 후진 −) |
| 9 | `implement` | 작업기 플래그. `1` = 내림(작업 중), `0` = 올림 |

실제 예시 (`samples/rddf/hackathon-3-original.rddf`, 전북 남원):

```
1	1	35.4200429	127.3906307	0.0	0.0	0.0	3.00	1
2	2	35.4200317	127.3905199	0.0	0.0	0.0	3.00	1
3	3	35.4200317	127.3905316	0.0	0.0	0.0	3.00	1
```

### 왜 "뒤에서" 세는가

열 위치를 앞에서 세면 두 형식이 어긋난다 — 9열에서는 2번째가 위도가 아니라
인덱스다. 다행히 뒤쪽 꼬리(`lat, lon, …, velocity, implement`)는 같아서,
파서는 **뒤에서 7번째를 위도, 뒤에서 6번째를 경도**로 읽는다. 두 형식 모두
이 기준으로 맞는다.

---

## 2. 좌표 표기와 변환

### DDMMSS.ssss → 십진도

`DDMMSS.ssss` 는 도(D)·분(M)·초(S) 를 자리로 이어 붙인 표기다.
예: `370913.5566` = 37° 09′ 13.5566″.

파서의 변환식 (`_ddmmss_to_deg` / `ddmmssToDeg`):

```
d = floor(|v| / 10000)          # 도
m = floor((|v| mod 10000) / 100) # 분
s = |v| mod 100                  # 초
deg = d + m/60 + s/3600          # v < 0 이면 부호 반전
```

### 두 형식의 판별 규칙 — 값 크기

파서는 열 수가 아니라 **값 크기**로 좌표 형식을 가른다:

- `|lat| ≤ 90` 이고 `|lon| ≤ 180` → 이미 십진도, 그대로 사용
- 그 밖 → DDMMSS.ssss 로 간주하고 위 식으로 변환

십진도 위도는 90 을 넘을 수 없으므로 두 형식이 겹치는 구간은 없다.

## 3. 파서 규칙 (실제 동작)

경로 파일을 만들 때 이 규칙을 지켜야 의도대로 읽힌다.

1. **행 단위 처리** — 줄바꿈(`\n`)으로 나누고 한 줄이 한 점이다.
2. **탭 구분 우선, 공백 폴백** — 먼저 탭(`\t`)으로 나누고 빈 토큰은 버린다.
   토큰이 7개 미만이면 그 줄을 **공백(연속 공백 포함)** 으로 다시 나눈다.
3. **7개 미만 열은 스킵** — 그래도 7개 미만이면 그 줄은 무시한다
   (빈 줄·주석성 줄이 자연스럽게 걸러진다).
4. **뒤에서 7번째 = 위도, 6번째 = 경도** — 숫자로 읽을 수 없으면 그 줄 스킵.
5. **좌표 형식 판별** — 위 2절의 값 크기 규칙.
6. **인접점 최대 간격 `MAX_STEP_M = 1000`(m)** — 직전에 채택된 점에서
   1,000 m 를 넘게 떨어진 점은 버린다. 원본 파일에 자릿수가 깨진 행이 섞인
   사례(예: `193134.xxxx` 사이의 `1930.970329` 한 줄)가 있는데, 그대로 두면
   그 점 하나 때문에 경로가 수백~수천 km 밖으로 튄다. 거리 계산은
   위도 1° = 111,320 m, 경도는 첫 점 위도의 `cos` 배율 근사를 쓴다.
7. **점이 2개 미만이면 빈 경로** — 선을 그릴 수 없는 입력으로 취급한다.

주의: 시뮬레이터·API 서버 파서는 위도·경도만 소비한다. `velocity` 와
`implement` 는 자율주행 앱이 읽는 값이므로, 경로를 직접 만들 때도 의미에 맞게
채워야 한다.

### 좌표 기준

- 자율주행 앱은 RDDF 의 **절대 위경도**를 그대로 쓴다.
- 시뮬레이터에서 경로가 밭 위에 보이려면 좌표가 해당 맵의 GPS 원점 근처여야
  한다. 기본 맵 원점은 **(37.5665, 126.9780)** — 샘플의 `-simworld` 파일들이
  이 원점 기준이다.

---

## 4. velocity 열

- **부호 = 주행 방향**: `+` 전진, `−` 후진. 후진 구간(헤드랜드 K-턴의 물러나는
  구간)은 반드시 음수로 넣는다 — 자율주행이 기어를 R 로 넘겨야 하는 지점이다.
- 값 스케일: 생성기(`make_plowing_rddf.py`)는 m/s 값을 넣는다 —
  작업 주행 `3.0`, 선회 `1.5`, 후진 `-1.0`. 실디바이스 8열 예시는 `4.000000`.

## 5. implement 열

작업기(플라우 등) 상태 플래그:

- `1` — 작업기 **내림**, 작업 중 (이랑 주행 구간)
- `0` — 작업기 **올림** (헤드랜드 선회·이동 구간)

`-simworld` 파일은 원본 코스 모양을 그대로 두고 시작점만 시뮬레이터 GPS 원점으로
옮긴 것이다. 경도 1° 의 실제 거리는 위도에 따라 다르므로 경도차에 cos 비율을
곱해 다시 쟀다 — 그냥 평행이동하면 코스가 동서로 늘어난다.

경로를 직접 만들 때는 `samples/rddf/make_plowing_rddf.py`(경운 코스 생성기,
차량 운동학 적분 방식)와 `make_test_paths.py`(직선·S-커브)를 출발점으로 삼으면
된다. 9열 십진도 형식으로 출력한다:

```python
rows.append(f"{i}\t{i}\t{lat:.7f}\t{lon:.7f}\t0.0\t0.0\t0.0\t{vel:.2f}\t{impl}")
```
